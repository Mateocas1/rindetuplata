# rindetuplata MVP

Argentine yield comparator ("¿Dónde rinde tu plata hoy?"): flagship portfolio project in Java/Spring Boot, built to become a real product.
Owner: Mateo. Built with AI under ODD. Read every section until `## Log` before working on a task.

### T2 design notes (orchestrator defaults; the owner may override)

- Package `ar.rindetuplata.domain` (pure Java, no Spring); tests in `src/test/java/ar/rindetuplata/domain`.
- `Money`: ARS amount, `BigDecimal`, rounded to 2 decimals `HALF_EVEN` only when presented; internal math uses `MathContext.DECIMAL128`.
- `AnnualRate` stores a nominal annual rate (TNA) as a fraction exactly as the source gives it; day count 365 (Argentine convention).
- Conversions: TEA for compounding every n days = (1 + TNA·n/365)^(365/n) − 1; daily accrual (n = 1) for remunerated accounts and money-market funds.
- Instruments for the saver MVP: plazo fijo (simple interest for the term: P·TNA·days/365; minimum term 30 days; minimum amount), remunerated account (daily accrual; cap: balance above the cap earns the rate given for the excess, 0 if none; tiers as ordered balance brackets), money-market fund (daily compounding at an observed TNA-equivalent). Conditional rates (e.g. Ualá "if you spend $X") are modeled as labeled conditions; the simulator uses the unconditional rate by default and reports the conditional one as "up to".
- Inflation: monthly INDEC rate for history; REM 12-month expected rate converted to a horizon of d days as (1 + r)^(d/365) − 1, never divided linearly.
- Real return = (1 + nominal return) / (1 + inflation over the same horizon) − 1.
- Ranking (S15): simulate every instrument for the user's amount and days; sort by final amount descending; ineligible instruments (minimum amount, minimum term) are returned separately with the reason, never silently dropped. Default amount 1,000,000 ARS, default days 30.
- Tests cover every formula with hand-computed expected values, cap boundaries (exactly at the cap, one peso over), minimum-term boundary (29/30 days), rounding, and the Naranja X example: 20% TNA capped at 1,000,000.

### T3 design notes (orchestrator defaults; the owner may override)

- Packages under `ar.rindetuplata.source` (Spring allowed here, never in `domain`): shared core in `source`; one subpackage per data kind: `plazofijo`, `fund`, `crypto`, `macro` (inflation, REM, PSP benchmark), `dollar`, `wallet`. Each kind has one port interface and one or more adapters; tests mirror the packages.
- Every adapter splits **parse** (pure: raw body bytes → records, used by T4 to replay the T9 archive) from **fetch** (Spring `RestClient` with connect/read timeouts and a `User-Agent`; base URLs in `@ConfigurationProperties` `rindetuplata.sources.*`). Parse tests read `src/test/resources/fixtures/` (see its README); fetch tests use `MockRestServiceServer` serving the same fixtures, including HTTP errors and malformed bodies. No live HTTP.
- Source records carry `SourceRef` (source id, display name, official yes/no), the data date given by the source (row-level when the source has one, S11/L-E), the fetch instant, `Confidence` and validation flags. `Confidence` values: `OFFICIAL_AUTOMATIC` (BCRA), `AGGREGATOR_AUTOMATIC` (ArgentinaDatos, dolarapi: automatic but not official; S12 names three levels, this fourth keeps the label honest), `SCRAPED_ENTITY_WEB` (Ualá), `CURATED_MANUAL` (with `verifiedAt`).
- Units are normalized at the adapter edge to fractions on `BigDecimal` (never `double`; parse JSON numbers as `BigDecimal`): BCRA percent (`21.1`), ArgentinaDatos plazo fijo fraction (`0.1925`), rendimientos `apy` percent, inflation percent. Each record keeps the rate basis as given (`TNA`, `TEA`, `APY`); TNA/TEA conversion happens in the domain, not in adapters.
- Validation layer flags, never drops: each row gets `List<ValidationFlag>` with severity `WARNING` (shown, usable) or `INVALID` (kept for audit, excluded from ranking downstream). Rules found in the recorded data: null or ≤ 0 rate → INVALID; rate > 300% → INVALID; data date older than a per-kind staleness window (plazo fijo 45 days, FCI 7 days, curated wallet 7 days) → WARNING `STALE`; ArgentinaDatos `tnaNoClientes` = 0 means "not offered to non-clients" (absent, not invalid; S19); BCRA `plazoMinimoInvertirDias` holds 0–5 in all 914 rows (Ualá lists two "PF TRADICIONAL" with codes 2 and 4 at different TEA), so it is an undocumented term code, never days: keep it raw as `termCode` with WARNING `TERM_CODE_UNDOCUMENTED`; products named `PPJJ` (legal entities) or in dollars are classified out of the saver persona, not deleted; FCI classes whose date lags the newest date in the same response by more than 7 days → WARNING `STALE` (the response contains dead classes dated 2020).
- Plazo fijo: BCRA transparency is primary (official TEA per product, entity code, channel, minimum amount); ArgentinaDatos is secondary and the only one with client vs non-client TNA (S19). A composite source returns both result sets; when one source fails it returns the other plus a `DEGRADED` status naming the failed source, and fails only when both fail.
- Macro: BCRA `estadisticas/v4.0/monetarias/{id}` client for variables 27 (monthly inflation, primary), 29 (REM 12-month expected), 1196 (PSP benchmark); ArgentinaDatos inflation as secondary for 27. The BCRA 400 body (`errorMessages`) becomes a typed source error.
- Wallet rates (S12): Ualá parser reads the T9 extract format (`matches` snippets) and, for live fetch, extracts snippets from the HTML with the same rules as `capture/extract_rates.py` (no new HTML dependency unless the worker shows it is needed); it yields the unconditional base rate (19% TNA between $10.000 and $1.000.000) and the conditional ones as labeled conditions ("up to" 24%), matching the domain `ConditionalRate`. Curated rates come from a classpath seed `curated-wallet-rates.json` (Naranja X 20% TNA up to $1.000.000, verified 2026-10-13) behind the same port; T6 replaces the seed with the admin panel. FCI-backed wallets map to fund classes in a classpath mapping (Mercado Pago → "Mercado Fondo - Clase A"; others only when the class is confirmed in the fixture); their yield is computed in T4 from cuotaparte deltas.
- FCI: cuotaparte quotes (fund, class, horizon, date, `vcp`, `ccp`, `patrimonio`) from `ultimo` and `penultimo`; no yield math in T3. Crypto/fintech: per platform and currency APY with date. Dólar MEP: buy, sell, update instant.
- Delivery in three work-unit commits made by the parent: (a) `source` core + `plazofijo`; (b) `fund`, `crypto`, `macro`, `dollar`; (c) `wallet`.

### T4 design notes (orchestrator defaults; the owner may override)

- Branch `feat/ingestion`. Packages: `ar.rindetuplata.store` (persistence), `ar.rindetuplata.ingest` (Spring Batch job, archive replay, scheduler, rebuild hook); `FundYield` in `ar.rindetuplata.domain` (pure Java). Tests mirror the packages.
- Dependencies: `spring-boot-starter-batch-jdbc` (verified on Maven Central for Boot 4.1.1) plus `spring-boot-starter-batch-test` only if it resolves; Batch 6 defaults to a resourceless repository, so the JDBC starter is required for one-instance-per-date idempotency. Batch metadata tables come from Flyway `V2__spring_batch_metadata.sql`, copied verbatim from `org/springframework/batch/core/schema-postgresql.sql` inside the resolved spring-batch-core jar; `spring.batch.jdbc.initialize-schema=never`, `spring.batch.job.enabled=false` (jobs are launched by our scheduler, never at startup).
- Writes use `JdbcClient` (no JPA entities in T4). Money and rates are `numeric` columns mapped to `BigDecimal`; flags, terms, tiers and conditions are `jsonb`.
- Schema `V1__instruments_and_snapshots.sql`:
  - `instrument(id bigserial pk, kind text, source_id text, natural_key text, display_name text, entity_name text null, segment text null, first_seen date, last_seen date, unique(kind, source_id, natural_key))`. Kinds: `PLAZO_FIJO_OFFICIAL`, `PLAZO_FIJO_BANK`, `FUND_CLASS`, `CRYPTO_YIELD`, `WALLET`. Natural keys: official = `entityCode|productName|channel|termCode|minimumAmount`; bank = `bankName`; fund = full class `name`; crypto = `platform|currency`; wallet = `walletId`. Upsert widens `first_seen`/`last_seen`, never narrows.
  - `rate_snapshot(instrument_id fk, capture_date date, data_date date, basis text, rate numeric null, client_rate numeric null, minimum_amount numeric null, details jsonb, confidence text, verified_at date null, fetched_at timestamptz, flags jsonb, invalid boolean, primary key(instrument_id, capture_date))`. `rate` = official TEA, bank non-client TNA, crypto APY, wallet base TNA (first unconditional tier); `client_rate` = bank client TNA; `details` = terms / tiers / conditions as given.
  - `fund_quote(instrument_id fk, quote_date date, vcp numeric, ccp numeric null, patrimonio numeric null, horizon text null, fetched_at timestamptz, confidence text, flags jsonb, invalid boolean, primary key(instrument_id, quote_date))`: a time series keyed by the source's own date.
  - `macro_observation(variable text, observation_date date, source_id text, value numeric, fetched_at timestamptz, confidence text, flags jsonb, primary key(variable, observation_date, source_id))`.
  - `dollar_quote(source_id text, capture_date date, buy numeric, sell numeric, updated_at timestamptz, fetched_at timestamptz, confidence text, flags jsonb, primary key(source_id, capture_date))`.
  - `source_run(capture_date date, source_id text, mode text, status text, rows int, failure text null, recorded_at timestamptz, primary key(capture_date, source_id))`: what each source produced for a date (`OK`, `DEGRADED`, `FAILED`, `MISSING_IN_ARCHIVE`).
- Idempotency: every writer replaces its slice in one transaction. Snapshots and dollar quotes: upsert on the primary key (`ON CONFLICT ... DO UPDATE`), so re-running a date leaves one row per instrument and date. Fund quotes and macro observations: upsert on their own date (a later run may correct a value). Rows flagged INVALID are stored (audit) with `invalid = true`, never dropped. If one response holds two rows with the same natural key, the writer keeps the first, counts the duplicates and reports them in `source_run.failure` text; it never fails the batch.
- `FundYield` (T4b): from two quotes of the same class, `(d0, vcp0)` and `(d1, vcp1)` with `d1 > d0`, calendar days `n = d1 − d0` (money-market funds accrue every calendar day): period return `vcp1/vcp0 − 1`; daily rate `(vcp1/vcp0)^(1/n) − 1`; TNA-equivalent for daily compounding `daily · 365` (feeds `MoneyMarketFund`'s `AnnualRate`); TEA `(vcp1/vcp0)^(365/n) − 1`. Rejects `n ≤ 0`, non-positive vcp, null inputs with `IllegalArgumentException`. `MathContext.DECIMAL128`, reuse `DecimalMath` for fractional powers. Tests: hand-computed values (incl. a 1-day and a 3-day weekend gap), a negative return, equal vcp → 0.
- Job (T4c): `dailyIngestionJob`, identifying job parameter `dataDate` (ISO date) plus non-identifying `mode` (`LIVE` | `REPLAY`). One step per data kind (plazo fijo, funds, crypto, macro, dollar, wallets), each a tasklet that obtains records, writes them and records `source_run`; a failing source marks its `source_run` `FAILED` and the step completes (one source never blocks the others, S5); the job is `COMPLETED` when every step ran. Restarting a failed instance re-runs only unfinished steps. Launching a date whose instance already COMPLETED is a no-op reported as such, not an error.
  - LIVE: fetch through the T3 ports (`PlazoFijoSource`, `FundSource` latest and previous, `CryptoYieldSource`, `MacroSource` for 27/29/1196, `DollarSource`, every `WalletRateSource` bean injected as a `List`), `dataDate` = today in `America/Argentina/Buenos_Aires`.
  - REPLAY: read the T9 archive from a local directory (`rindetuplata.ingest.archive-dir`, a checkout of the `data` branch): `raw/yyyy/MM/dd/manifest.json`, then each source with `status: ok` through the T3 static `parse` methods (`fetchedAt` = manifest `captured_at`): `bcra-transparencia-plazos-fijos` → `BcraPlazoFijoAdapter.parse`, `argentinadatos-plazo-fijo` → `ArgentinaDatosPlazoFijoAdapter.parse`, `argentinadatos-rendimientos` → `ArgentinaDatosCryptoAdapter.parse`, `uala-cuenta-remunerada` → `UalaWalletAdapter.parseExtract`. ### T5 design notes (orchestrator defaults; the owner may override)

- Branch `feat/public-api`. Packages: `ar.rindetuplata.ranking` (T5a: read queries over the T4 tables with `JdbcClient`, mapping to `domain` instruments, `RankingService`, result records; Spring allowed, no web types); `ar.rindetuplata.api` (T5b/T5c: controllers, JSON DTOs, error handling, OpenAPI). - Ranking input (T5a): `RankingQuery(Money amount, int days, Set<Long> clientOf, Set<RankedKind> kinds, LocalDate asOf, int limit)`. Defaults: amount 1,000,000, days 30, `clientOf` empty, all kinds, `asOf` = today in `America/Argentina/Buenos_Aires`, limit 50 (max 200). `RankedKind`: `PLAZO_FIJO`, `WALLET`, `FUND`, `CRYPTO`.
- Which rows (T5a): for each instrument kind, the latest `capture_date` ≤ `asOf` that has rows of that kind (kinds never mix dates; one failing source falls back to its last good day, and that row shows its own dates). Rows with `invalid = true` go to `excluded` with reason `INVALID_DATA` and their flags; WARNING flags travel with the ranked entry.
- Mapping to the domain (T5a). The public id of every instrument is the `instrument.id` as a string.
  - `PLAZO_FIJO_BANK` → `PlazoFijo` (minimum 30 days, minimum amount from the snapshot or 0). Rate: non-client TNA (`rate`) by default; client TNA (`client_rate`) when the instrument id is in `clientOf`; for a client, the `details.terms` band whose [minDays, maxDays] and [minAmount, maxAmount] (null = open) contain the request replaces the base client rate. Chosen rate null → `excluded` with `NOT_OFFERED_TO_NON_CLIENTS` (or `NO_CLIENT_RATE` for a client). The entry says which rate was used (`NON_CLIENT`, `CLIENT`, `CLIENT_TERM_BAND`).

Curated rates keep `verified_at`.
  - FCI-backed wallets (`FciBackedWalletCatalog.fromClasspath()`): an entry named after the wallet (e.g. Mercado Pago), kind `WALLET`, ranked as a `MoneyMarketFund` at its class's yield, with the class name as its source detail.
  - `FUND_CLASS` → `MoneyMarketFund` at the `FundYield` TNA-equivalent of its two latest non-invalid quotes with `quote_date` ≤ `asOf`. Excluded reasons: `INSUFFICIENT_HISTORY` (one quote), `STALE` (latest quote more than 7 days before `asOf`), `NEGATIVE_RETURN` (vcp fell: never ranked, S12/T4 note).
  - `CRYPTO_YIELD` → only currency `ARS`, as a `RemuneratedAccount` with one unbounded tier at the TNA equivalent of the APY for daily compounding: ((1 + APY)^(1/365) − 1) · 365 (`DecimalMath`). Other currencies are out of the saver persona: ignored by the ranking (listed by T5b).

- Result (T5a): request echo, inflation, `ranked` (limited), `ineligible` (domain `Ineligible`: minimum term/amount, with detail), `excluded` (reason + flags), and totals before the limit. Each entry: id, kind, name, entity, source (id, display name, official), confidence, `verifiedAt`, `captureDate`, `dataDate`, rate used (fraction, basis TNA) and its kind, final amount, earned, nominal return, real return, "up to" outcome, WARNING flags. Single simulation (`RankingService.simulate(id, amount, days, client)`) returns one such entry or its ineligible/excluded reason; an unknown id is a typed not-found.
- JSON (T5b/T5c): money with scale 2 `HALF_EVEN` (`Money.presented()`), rates and returns as fractions with scale 6 `HALF_EVEN`, both as JSON numbers; dates ISO. Errors are `ProblemDetail` (RFC 9457): 400 for invalid amount/days/limit/kind/date range with the offending parameter named, 404 for an unknown instrument. Every response states the data dates (S11); no advice wording.
